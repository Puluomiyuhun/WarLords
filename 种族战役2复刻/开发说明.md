## 0.5 双窗口合作与原作界面

- `coop-local-server.cjs` 将静态网页和 `/ws` 放在同一 `127.0.0.1:18642` 服务；`开始双窗口合作.cmd` 查找当前电脑的 Node.js 并打开页面。
- `coop.html` / `coop.js` / `coop.css` 提供创建、加入、每窗独立席位、同步战斗、商店和关卡切换。页面只提交操作，战斗与交易由相邻目录的 `coop-room-server.cjs`、`coop-campaign.cjs` 决定。
- 战斗规则版本仍为 0.4.0，合作协议为 1。客户端按 24 Hz 状态渲染，双方资源就绪后才计时；断线暂停并允许 30 秒恢复，手动暂停同样作用于双方。
- 合作战场复用单人 `style.css`、`layout.js` 及原 HUD 素材：700×500 舞台、左上五列两排圆形头像、原尺寸金属栏。两位玩家各自在自己的浏览器左上角选兵，友军信息在右上。
- 商店按来源根时间轴第 6 帧及符号 1884 还原：内容偏移约 (40,70)，兵种两列间距 340、每行 75；详情大头像 163×162，左属性条、右升级列表，底部返回与继续/准备。
- `shop-source-data.js` 保存原始展示伤害和升级图标映射；`shop-source-*` 头像使用原商店锚点，边饰来自符号 978 / 1864 / 1884，升级图标来自 1011。运行不读取 SWF。
- `shop-ui.js` 支持本地规则和服务器确认两种交易回调；此轮只替换 UI，价格、购买资格、战斗机制未改。合作整备时准备按钮直接复用商店页脚。
- 新增 `local-browser-tests.cjs` 验证本机页面/素材、路径边界、HEAD/方法和 WebSocket 来源；`coop-tests.cjs` 覆盖素材屏障、暂停与刷新恢复。

当前合作只用于本机两个页面，三个关卡按需求编写；没有部署公网服务器、合作音效或跨服务重启存档。此包需保留「种族战役2复刻」「联机预研」「合作模式预研」三个相邻目录。

# 战斗版 0.4 实现说明

独立 JavaScript 战斗引擎 + Canvas 显示层。运行不读取 SWF、不执行 ActionScript，也不依赖 Ruffle。范围为九种族、二十一种兵的八路野战。

## 文件与修改入口

| 文件 | 职责 |
|---|---|
| `engine.js` | 24 Hz 模拟、动作事件、攻击/格挡/击倒、弹道、AI、胜负与存档 |
| `content.js` | 原始数值、动作、种族兵种列表与图集元数据 |
| `progression.js` / `shop-ui.js` / `shop.css` | 共用军备、购买/售出/升级规则与商店界面 |
| `balance.js` | 可编辑生命、速度、充能等数值；当前保持来源数值 |
| `app.js` | 渲染、键鼠/触控、声音、资源加载与浏览器存档 |
| `layout.js` | 来源舞台、八路透视、坐标投影与选路 |
| `index.html` / `style.css` | 原版风格界面、两排头像、手机横竖屏控制面板 |
| `data/units.json` | 研究数据副本，运行时不直接加载 |
| `data/asset-memory-v04.json` | 以图集宽×高×4 估算的 RGBA 体积 |
| `assets/` / `assets/mobile/` | 完整分辨率 / 半分辨率角色图集 |
| `Launcher.cs` / `开始游戏.exe` | Windows 本机静态资源服务 |
| `tests.cjs` / `layout-tests.cjs` / `expansion-tests.cjs` | 战斗、几何、扩展内容测试 |

改数值通常编辑 `balance.js`；改命中时机编辑帧事件；新增战斗机制编辑 `engine.js`。UI 与模拟分离。新兵种需要相应皮肤、动作及图集元数据，不能只添加名称。改规则后应开始新战斗；未来联机需同步提升 `rulesVersion`。

## 素材与动作

来源是用户提供的完善版，SHA256：`b655fb6a2543ff8131fa6650c1533dc10640f50f08874892ba0b83bd2cd778ae`。

使用 JPEXS FFDec 导出临时 SWF 副本。固定带种族标签的嵌套皮肤时间轴，再导出完整动作，避免皮肤轮换。原 0.3 有 73 组兵种动画；0.4 新增九组战斗法师、三组权杖施法者，以及两组魔法弹动画。另有九组通用击倒动画。权杖施法者每组仅打包当前路径可到达的 137 帧，保留原时间轴索引，其余法术暂不开放。

来源 `ready`、`moveman`、`attack`、`impact`、`firearrow`、帧调用和跳转转为有限数据事件，不执行原脚本文本。武士重复调用展开为两倍速度突进；盾兵处理格挡开关和回到准备帧；重击使用半威力随机伤害及推退/击倒条件。倒地使用原减速和 38→35 随机循环，起身后恢复战斗。引擎保留单位 ID，原 AS 则删除并重建对象。

逐帧裁掉透明空白，保留原 RECT 对应锚点，装入不超过 2048×2048 的图集页。手机图集缩小一半，显示尺寸与脚底锚点不变。开局只载入双方所需图片；手机/窄屏启动选小图集，桌面保留原尺寸。体积估算不等于实测浏览器或 GPU 内存，背景、Canvas、JS 和临时解码另计。

## 来源规则与几何

- 700×500 逻辑舞台，Canvas 缓冲区 1400×1000；界面整体等比缩放。
- game（1755）缩放 0.245758056640625；Lane（1092）使用来源宽高及透视除数。
- 最近路脚底 y≈439.46、最远路 y≈227.07。±1400 出兵，越过 ±1450 计分，按远到近绘制。
- 普通攻击取具体动作威力并处理随机伤害和克制；近战范围使用来源单位的两倍缩放。
- 弓箭手 10 支箭，初速度 50，重力每 tick 加 1，使用来源预测公式。
- 7200 tick 时间限制，净领先 25 分获胜，平分加时。
- 存档 v3 增加玩家归属、升级、特殊状态与魔法弹；兼容 v1/v2。合作战役有单独封装格式，不能导入普通野战 HUD。

## 已知差异

1. 商店和首批升级/魔法已接入；完整战役、全部法术、部分种族被动、全军冲锋、骑兵与攻城未迁移。
2. 箭矢采用范围判定，没有复制 Flash 对象 `hitTest`、完整反弹和地面残留。
3. AI 未完整迁移所有概率、关卡难度、隐式共享变量和原始缺陷。
4. 普通死亡和基础击倒已迁移；血液、斩首、掉落武器、受击装备和动态着色仍有差异。
5. 固定种子随机数保证同版本重放，但不是 Flash 的同一随机序列。
6. 字体、文字位置、充能特效仍有差异；新增兵种尚未全部与原游戏录像逐帧验收。
7. 手机仅做桌面浏览器视口测试，真实 iPhone Safari 的内存、帧率和音效待验收。

## 开发与运行

无前端构建框架或第三方前端依赖，编辑后刷新即可。Node.js 下运行：

```text
node tests.cjs
node layout-tests.cjs
node expansion-tests.cjs
node upgrade-magic-tests.cjs
```

启动器使用 Windows .NET Framework 的 C# 编译器，引用 System.Windows.Forms.dll 和 System.Drawing.dll，以 winexe 目标编译 `Launcher.cs` 即可重建。仅监听 `127.0.0.1:18632`，未修改防火墙或安装服务。

同级 `联机预研` 文件夹有共用本引擎的房间服务原型、网络测试、基准与研究报告。原型只监听回环地址，尚未接入游戏界面。


## 0.4 升级、法师与合作接口

`unit.owner` 表示控制玩家，`unit.side` 表示敌我阵营；普通对战阵营为 [0,1]，合作为 [0,0,1]。每人独立军备、充能和路线。同侧目标不攻击、不伤害；三支军队分别使用自己的种族图集。

`content.js` 带原升级表，17 项设为 supported；未实现项在商店禁用。特殊能力需先购买，再等待两倍原充能。普通魔法弹发射于战斗法师第 128 帧；光球来自权杖施法者第 225 帧，按原逻辑概率触发，每名施法者最多十次。当前没有把普通战斗法师当成消耗箭支的弓箭手。

原脚本部分升级类别同时出现中文数据与英文判断，本版将其规范化到 armour/speed/attack 等键，以使来源升级按说明实际生效。装备外观变化未全面实现。剑士特殊帧 127–137 只有举盾标记、没有 moveman，故本完善版表现为原地举盾。斧兵 137–139 帧逐次减速，146 帧独立复位速度，不能只在移动帧处理速度事件。

商店售兵对照 DefineSprite_1884/frame_50：Math.round(购买价格/2)；RemoveUnitType 只移除军队列表，因此保留升级。当前起始四兵种不可售出，属于本版军备保底限制。军备浏览器键为 warlords2-armies-v1，按玩家与种族分别保存；野战 3000 试用资金，合作 500 初始资金。

合作研究入口见相邻「合作模式预研」。其关卡控制器已经复用本引擎和商店模型，尚未连接浏览器合作 HUD。联机状态元组增加 owner、specialLevel 与魔法类型/动画帧/方向；客户端必须按 0.4.0 规则配套实现。
